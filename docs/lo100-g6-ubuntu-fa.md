# نصب Ubuntu روی G6 / Lights-Out 100 از پنل

مسیر G6 از مسیر Redfish سرورهای G9/G10 جداست، ولی از همان فرم‌های پارتیشن‌بندی، شبکه و بازبینی دیسک‌های پنل استفاده می‌کند. دسترسی به سیستم‌عامل قبلی لازم نیست. فعلاً Ubuntu Server 24.04 پشتیبانی می‌شود.

## مراحل کار

1. در فرم اتصال، Lights-Out 100 را انتخاب و با اطلاعات کنترلر متصل شوید.
2. «بررسی بدون ریبوت» مشخصات شاسی را از خود LO100 می‌خواند. اگر گزارش تشخیصی قبلی همین GUID و شماره‌سریال موجود باشد، دیسک‌ها در فرم پارتیشن‌بندی قرار می‌گیرند. این اطلاعات کش‌شده است و شناسایی تازهٔ دیسک‌ها محسوب نمی‌شود؛ قبل از نصب شناسه، اندازه و حالت بوت دوباره کنترل می‌شود.
3. اگر شناسایی قبلی موجود نبود، «ریبوت برای شناسایی زنده» را علامت بزنید و دکمهٔ شناسایی زنده را بزنید. ISO تشخیصی ساخته می‌شود. ابتدا اتصال خودکار رسانه روی IP و پورت انتخابی (پیش‌فرض G6: TCP/443) امتحان می‌شود. بدون تأیید کانال رسانه هیچ ریبوتی درخواست نمی‌شود.
4. اگر اتصال خودکار تأیید نشد، پنل مسیر ISO تشخیصی را نشان می‌دهد. فقط در این حالت کنسول Java را باز کنید، آن ISO را به CD/DVD متصل کنید و گزینهٔ «ISO تشخیصی را متصل کرده‌ام» را علامت بزنید؛ سپس با تأیید ریبوت، شناسایی زنده را دوباره بزنید. پس از تأیید رسانه، پنل انتخاب یک‌بارهٔ CD در حالت BIOS را از IPMI درخواست و بازخوانی می‌کند؛ اگر بازخوانی تأیید نشود فرمان ریبوت ارسال نمی‌شود. ترتیب دائمی بوت تغییر نمی‌کند.
5. برنامه پیش از فرمان بوت، کنسول سریال LO100 را به حالت دریافت وصل می‌کند. Linux تشخیصی دیسک‌ها، by-id، MACها، GUID، سریال و BIOS/UEFI را گزارش می‌کند. شناسهٔ یکتای همان اجرا و هویت سرور بررسی می‌شوند. گزارش قدیمی یا متعلق به سرور دیگر پذیرفته نمی‌شود. زمان انتظار در پس‌زمینه است و پنل باز می‌ماند.
6. پس از دریافت گزارش معتبر، همان ویرایشگر پارتیشن معمولی فعال است. شبکه را تنظیم کنید یا «فعلاً تنظیمات شبکه را رد کن» را فعال نگه دارید. رمز حساب جدید را وارد و ISO نصب را آماده کنید. حساب Ubuntu این مسیر `provision` با sudo است.
7. دیسک‌های انتخابی و دست‌نخورده را بازبینی و INSTALL را وارد کنید. ابتدا اتصال خودکار ISO نصب امتحان می‌شود. اگر تأیید نشد، بدون ریبوت به مرحلهٔ آماده برمی‌گردید؛ در صورت نیاز ISO نصب را در Java متصل، گزینهٔ اتصال دستی نصب را علامت و INSTALL را تکرار کنید. فایل تشخیصی با فایل نصب متفاوت است.
8. نصب از طرح بازبینی‌شده انجام می‌شود و برای جلوگیری از نصب مجدد با ISO متصل، در پایان خاموش می‌شود. رسانه را قطع و سرور را از دیسک بوت کنید. تأیید نهایی این مسیر فعلاً با ورود واقعی اپراتور و VERIFIED است؛ ارسال فرمان بوت، نصب موفق تلقی نمی‌شود.

## شواهد و محدودیت‌ها

- روی DL160 G6، LO100 4.26 Advanced، HTTP و CLP فقط مشخصات شاسی و FRU را داده‌اند؛ شناسهٔ دیسک‌ها از این منابع به دست نیامد. بدون گزارش قبلی و بدون دسترسی به OS، برای اولین شناسایی واقعی دیسک‌ها بوت تشخیصی لازم است. از نام فرضی /dev/sda استفاده نمی‌شود.
- خواندن فعلی Boot Flags با IPMI روی این سخت‌افزار موفق بود: هیچ override فعالی وجود نداشت. نوشتن انتخاب یک‌بارهٔ CD فقط در عملیات تأییدشدهٔ پنل انجام می‌شود؛ تست واقعی نوشتن و بوت هنوز اجرا نشده است. گزارش: `generated/lo100-ipmi-readonly.json`. پیاده‌سازی مستقل و بدون ipmitool یا دسترسی ادمین است؛ قالب بسته با [مرجع ipmitool](https://github.com/ipmitool/ipmitool/blob/master/src/plugins/lan/lan.c) تطبیق داده شده است.
- خواندن شماره‌سریال و اتصال فقط‌خواندنی کنسول سریال از CLP در سخت‌افزار بررسی شده است. دریافت گزارش Linux بعد از بوت هنوز نیازمند تست اپراتور است؛ تنظیمات BIOS تغییر نکرده‌اند.
- رسانهٔ LO100 مانند Redfish یک URL HTTP نیست؛ خود کنترلر به listener رسانه در جامپ‌سرور متصل می‌شود. TCP/443 در این مسیر HTTPS نیست و تعویض شمارهٔ پورت، فایروال را دور نمی‌زند. قواعد فایروال تغییر نکرده‌اند.
- آداپتور native جدید از پروتکل مهندسی معکوس با مجوز MIT استفاده می‌کند (`src/_lo100_wire/LICENSE`). انتقال سکتور ISO با سوکت واقعی محلی و کنترلر شبیه‌سازی‌شده تست شده؛ سازگاری انتقال کامل و بوت با این سخت‌افزار هنوز تأیید نشده است. مسیر دستی جایگزین همچنان موجود است.
- گزارش آزمون واقعی بدون ریبوت روی پورت 443: `generated/lo100-native-443-validation.json`. در این آزمون storage_allowed و full_control هر دو false بودند و callback دریافت نشد؛ محل قطع ارتباط یا بسته‌بودن پورت اثبات نشده است. آداپتور اکنون پیش از ثبت رسانه، مجوز مؤثر جلسه را بررسی می‌کند و جلسهٔ دیگر را به‌اجبار قطع نمی‌کند.
- ISO تشخیصی فقط اطلاعات می‌خواند و در early-command می‌ماند؛ از مرحلهٔ نصب عبور نمی‌کند. حتی بازگشت غیرمنتظرهٔ اسکریپت باعث خطا می‌شود. رفتار early-command طبق [مستندات رسمی Ubuntu](https://canonical-subiquity.readthedocs-hosted.com/en/latest/reference/autoinstall-reference.html) است.

تست‌های ریبوت و نصب واقعی در این بازبینی اجرا نشده‌اند و باید از پنل توسط اپراتور انجام شوند. هیچ نتیجهٔ تست شبیه‌سازی‌شده به‌عنوان موفقیت سخت‌افزاری گزارش نشده است.
